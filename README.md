# HC Capital — «Капитал талантов»

Рабочий сайт: https://hc-capital.ru/ — хостинг REG.RU.

## Где редактировать

| Файл | Назначение |
| --- | --- |
| public/index.html | Главная, тексты, пакеты и контакты |
| public/assets/css/style.css | Оформление, адаптивность и анимация |
| public/assets/js/main.js | Меню, панели, выбор пакета, документы |
| public/assets/js/request-form.js | Форма, проверка, отправка и повтор без дублей |
| public/assets/js/legal-docs.js | Тексты политики и согласия |
| public/assets/img/ | Фотографии и изображения |
| public/assets/fonts/ | Шрифты на собственном хостинге |
| docs/consent/ | Неизменяемые снимки редакций согласия; новая редакция также устанавливается в закрытой части REG.RU |

Единый адрес для контактов и получения заявок — **hc-capital@mail.ru**. Ящик site@hc-capital.ru служит только техническим SMTP-отправителем. Заявки сначала сохраняются в базе REG.RU, затем очередь отправляет письмо на Mail. Планировщик обрабатывает очередь раз в минуту; это не гарантирует мгновенное попадание во входящие.

## Обновление сайта

Изменения → commit → push в main → GitHub Actions → проверки → резервная копия → публикация на REG.RU → проверка сайта по HTTPS.

При pull request выполняются только проверки. Опубликовать текущий main повторно можно через Actions → «Проверка и публикация на REG.RU» → Run workflow.

Результат запуска: https://github.com/Foxiras/HR-manager/actions

На сервере можно проверить версию: https://hc-capital.ru/release.json — поле source_commit совпадает с коммитом GitHub.

Ресурсы каждого коммита имеют собственный адрес assets/releases/COMMIT/, поэтому прежняя страница не смешивается с новыми стилями. Документы и главная переключаются после загрузки ресурсов.

## Что защищено от автоматической замены

GitHub-публикация обновляет только статические страницы и ресурсы. Существующие PHP API, база данных, очередь писем, SMTP-настройки и закрытая папка остаются на REG.RU. Для изменения серверного кода используется отдельная проверка и ручная публикация, как при первоначальной установке.

Секрет REGRU_SSH_KEY хранится только в GitHub Actions Secrets. Приёмник scripts/receive.py ограничивает этот ключ командой публикации, проверяет архив и запрещает PHP, .htaccess, переходы за каталог, ссылки и произвольные команды. Приватные ключи, реальные config.php, пароли и заявки в Git не добавляются.

## Проверки локально

```text
python scripts/check_site.py
python -m unittest discover -s tests -v
```

Для check_site нужен Node.js. Для просмотра public/ можно использовать любой локальный HTTP-сервер; рабочая форма требует существующего PHP API REG.RU.

## История и откат

История старой версии сохранена в предыдущих коммитах. Перед каждым обновлением сервер сохраняет прежние корневые страницы в backups/hc-capital-git-… вне каталога сайта. Ресурсы прежних релизов сохраняются.

Обычный откат: отменить нужный коммит через git revert и push в main. Это создаёт новый проверенный релиз с предыдущим содержимым. Для отката базы или PHP требуется отдельное решение — эта автоматизация их не изменяет.

GitHub Pages больше не используется как хостинг этого сайта.
