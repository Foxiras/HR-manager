# Установка новой версии hc-capital.ru

Сборка от 21 октября 2026 года. Получатель и отправитель писем — site@hc-capital.ru. Исходные DOCX не изменялись; HTML-документы подготовлены на их основе с новым адресом, датой редакции и описанием новой схемы обработки. Проверьте реквизиты и фактическую схему перед публикацией. Размещение файлов само по себе не подтверждает выполнение всех требований законодательства.

## 1. Где разместить файлы

Сначала сохраните имеющийся index.html хостинга за пределами папки сайта.

* Содержимое `public/` → `www/hc-capital.ru/`. Заменяется index.html, копируются папки styles, images, fonts, api, legal-страницы и .htaccess. Саму папку public копировать не нужно.
* Содержимое `private/` → отдельная папка `hc-capital-private` в домашнем каталоге аккаунта, РЯДОМ с `www`, а не внутри `www` или сайта.
* `database/schema.sql` импортируется через phpMyAdmin в базу `u3690832_hc_requests`. SQL, инструкция и полный архив НЕ загружаются в публичный каталог.

Ожидаемая структура:

```text
домашний каталог аккаунта/
  www/hc-capital.ru/index.html
  www/hc-capital.ru/api/request.php
  hc-capital-private/bootstrap.php
  hc-capital-private/config.php
  hc-capital-private/worker.php
  hc-capital-private/consent/2026-10-21.txt
```

В API путь к закрытой папке вычисляется относительно `www/hc-capital.ru/api/`. Если фактическая структура другая, исправьте переменную `$private` в api/request.php. Закрытая папка не должна обслуживаться никаким доменом или псевдонимом. Установите права на неё 700, на config.php — 600 (если PHP работает от владельца аккаунта).

## 2. Настройки без передачи паролей в чат

В закрытой папке скопируйте config.example.php в config.php. В редакторе ispmanager заполните:

* db.password — пароль пользователя `u3690832_hc_form`.
* db.host — адрес MySQL из настроек услуги. `localhost` в примере — предположение; проверьте его при подключении.
* smtp.password — отдельный пароль ящика site@hc-capital.ru.
* rate_secret — случайная строка не короче 32 символов из менеджера паролей; сохраните её.

SMTP: mail.hosting.reg.ru, порт 465, SSL/TLS. Логин, отправитель и получатель — site@hc-capital.ru. Поле enabled пока оставьте false. Пароли не размещайте в GitHub, HTML, JavaScript, SQL или переписке.

## 3. Проверка PHP и почты

В Shell-клиенте панели выполните команды, заменив `/ПОЛНЫЙ/ПУТЬ` реальным абсолютным путём. Путь можно узнать в менеджере файлов/Shell командой pwd.

```sh
/usr/bin/php /ПОЛНЫЙ/ПУТЬ/hc-capital-private/check.php
/usr/bin/php /ПОЛНЫЙ/ПУТЬ/hc-capital-private/check.php --send-test
```

Нужен PHP 8.3 или новее, расширения pdo_mysql, mbstring, openssl; для Telegram ещё curl. CLI-версия PHP может отличаться от выбранной версии сайта: проверьте `/usr/bin/php -v`, при необходимости используйте путь к PHP 8.3 из панели/поддержки.

Второй вызов отправляет одно техническое письмо без персональных данных. Убедитесь, что оно появилось во входящих или спаме. SMTP Accepted означает принятие сервером, а не гарантированное попадание во входящие.

## 4. Очередь писем и удаление

Добавьте в «Планировщик CRON» две задачи:

```cron
* * * * * /usr/bin/php /ПОЛНЫЙ/ПУТЬ/hc-capital-private/worker.php
15 3 * * * /usr/bin/php /ПОЛНЫЙ/ПУТЬ/hc-capital-private/cleanup.php
```

Worker раз в минуту доставляет сохранённые заявки и повторяет неудачные отправки с увеличением интервала. Заявка считается принятой только после записи в БД. При неоднозначном обрыве соединения после принятия письма SMTP возможен повтор письма с тем же Message-ID/номером заявки. Отслеживайте вывод CRON и очередь: нулевое число необработанных писем — нормальное состояние после доставки.

Cleanup удаляет из базы заявки без договора через 90 дней после last_interaction_at; технические метки ограничения частоты удаляются также worker. Последующую переписку база автоматически не видит: оператор должен обновлять last_interaction_at при взаимодействии, а при заключении договора задавать retain_for_contract=1 и отдельно контролировать законный срок хранения. По умолчанию last_interaction_at — время подачи заявки.

Автоочистка БД НЕ удаляет письма, вложения, резервные копии или журналы хостинга. Для них нужен отдельный порядок удаления, включая копии в папках «Отправленные», «Корзина» и «Спам». Журнал согласий хранится в строке заявки и удаляется вместе с ней; отдельное более длительное хранение требует согласованного основания и срока.

## 5. DNS и запуск

До переключения DNS проверьте новую версию на сервере с локальным сопоставлением имени и IP хостинга (hosts) либо способом предварительного просмотра, который предложит поддержка. Не отправляйте реальные данные через HTTP или самоподписанный сертификат. Форма принимает только HTTPS и два адреса: hc-capital.ru, www.hc-capital.ru.

Сохраните текущие DNS-записи. При переключении сайта на новый IP настройте корневое имя и www; проверьте оставшиеся A/AAAA/CNAME, чтобы часть посетителей не попадала на старый сервер. Не удаляйте посторонние записи вслепую. Для почты потребуются MX, SPF и DKIM, соответствующие настройкам Рег.ру; DMARC вводите с согласованной политикой после проверки отправки. Создание почтового домена в панели само по себе не гарантирует появления записей на действующих авторитетных DNS.

Выпустите доверенный SSL для hc-capital.ru и www.hc-capital.ru, включите перенаправление HTTP→HTTPS. HSTS можно добавить после проверки HTTPS. Проверьте входящие письма на site@hc-capital.ru с внешнего адреса и исходящую доставку.

После успешной проверки БД, почты и CRON установите enabled=true в закрытом config.php. Отправьте согласованную тестовую заявку, проверьте строку БД, consent_given=1, consent_version, consent_sha256 и mail_sent_at, затем удалите тестовые данные и письмо. До этого не считайте приём заявок рабочим.

Сайт использует один необходимый сеансовый cookie hc_form для защиты формы. Внешняя аналитика, рекламные пиксели и внешние шрифты не подключены. Проверьте также настройки журналов, бэкапов, доступов, уведомление оператора в Роскомнадзор и фактическое размещение инфраструктуры у провайдера.

## 6. Telegram — необязательно

По умолчанию выключен. После отдельной настройки укажите token и chat_id только в config.php, затем enabled=true внутри telegram. Worker отправляет только «Новая заявка на сайте. Проверьте почту.» после принятия письма SMTP. Никакие поля формы, номер заявки, имя, телефон или сообщение в Telegram не отправляются. После пяти неудачных попыток уведомления требуется ручная проверка настройки и сброс telegram_attempts для повторения.
